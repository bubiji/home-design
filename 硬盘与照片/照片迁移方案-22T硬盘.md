# MacBook 照片库 → 22T 移动硬盘 专业迁移方案

**适用情况**：iCloud 照片已开启且为「优化 Mac 存储」；主账号在 Mac 本机 + 第二个 Apple 账号在虚拟机；目标是迁到 22T 硬盘、用开源软件长期管理、并释放 MacBook 空间。

---

## ⚠️ 开始前必读的三条红线

1. **「优化 Mac 存储」意味着本机没有全部原图**——Photos 库里很多只是缩略图，直接拷贝 `.photoslibrary` 文件到硬盘会得到一个残缺的库。必须先补齐原件再导出。
2. **iCloud 开启时，在 Photos App 里删照片 = 同步删掉 iCloud 云端**（进入"最近删除"，30 天后彻底消失）。释放本机空间**绝不能**用"在 Photos 里删"这一招，正确做法见第 6 步。
3. **22T 单盘不是备份**（RAID1 也不是备份，单盘更不是）。在你办公室服务器/RAID 就绪、形成第二份拷贝之前，**先保留 iCloud 云端这份**，它是免费的过渡保险。

---

## 第 0 步：准备 22T 硬盘

- **格式**：
  - 如果这块盘近期主要接 Mac、以后通过网络拷进你计划的 Linux 服务器 → **APFS（加密可选）**，最稳。
  - 如果确定以后要**直接插到 Linux 服务器**上用 → 用 **exFAT**（两边都能读写，但无日志、无权限，仅适合当搬运/归档盘）。
- **目录规划**（按账号分层，日期分月）：

```
/Volumes/Archive22T/Photos/
├── dean-main/          # 主账号
│   └── 2024/05/IMG_1234.heic + IMG_1234.xmp
└── account2-vm/        # 虚拟机里的第二账号
    └── ...
```

---

## 第 1 步：补齐 iCloud 原件（主账号）

打开 **Photos → 设置 → iCloud**，查看库的实际大小与照片数量（记下总数，后面对账用）。

- **情况 A：MacBook 剩余空间放得下整个库** → 切换为「**下载原件到此 Mac**」，插电挂机等它下完（底部状态栏会显示进度；网络面板无下载流量、状态消失即完成）。
- **情况 B：MacBook 空间不够** → 不用切换，保持优化存储，后面用 osxphotos 的 `--download-missing` 边下边导，或直接用 icloudpd 从云端拉到硬盘（见第 3 步备选）。

---

## 第 2 步：安装开源工具 osxphotos

[osxphotos](https://github.com/RhetTbull/osxphotos) 是 Photos 库迁移的事实标准开源工具：能读取 Photos 数据库，导出原件+编辑版+Live Photo 视频，并把相册、人物、关键词、位置、时间等元数据写成 XMP sidecar——这正是 Immich/PhotoPrism 能读懂的格式。

```bash
brew install uv          # 如果还没有 uv
uv tool install --python 3.13 osxphotos
```

---

## 第 3 步：导出主账号（核心命令）

```bash
osxphotos export /Volumes/Archive22T/Photos/dean-main \
  --library ~/Pictures/Photos\ Library.photoslibrary \
  --download-missing --retry 3 \
  --directory "{created.year}/{created.mm}" \
  --sidecar XMP --sidecar-drop-ext \
  --touch-file \
  --update \
  --report /Volumes/Archive22T/Photos/dean-main-report.csv
```

各参数含义：

- `--download-missing --retry 3`：遇到本机没有原件的照片，自动从 iCloud 下载再导出，失败重试 3 次（解决「优化存储」问题的关键）。
- `--directory "{created.year}/{created.mm}"`：按 `年/月` 建目录。
- `--sidecar XMP`：每张照片旁写一个 .xmp 元数据文件（相册、人物、GPS、关键词都在里面）。
- `--touch-file`：把文件修改时间设成拍摄时间，任何软件按时间排序都正确。
- `--update`：**断点续传**。中断了、或以后又拍了新照片，重跑同一条命令只会导出增量——大库分几晚跑完全没问题。
- `--report`：生成 CSV 清单，逐张记录导出结果，用于对账。

默认会同时导出**原图和编辑后版本**（`_edited` 后缀）以及 Live Photo 的 `.mov`，归档最完整，无需额外参数。

> **备选：icloudpd**。如果库远大于本机空间、`--download-missing` 太慢，可用另一个开源工具 [icloudpd](https://github.com/icloud-photos-downloader/icloud_photos_downloader) 直接从 iCloud 服务器下载原件到 22T 盘，完全不占 Mac 空间：
> `uv tool install icloudpd && icloudpd --directory /Volumes/Archive22T/Photos/dean-main --username 你的AppleID --folder-structure {:%Y/%m}`
> 代价是拿不到相册结构和 Photos 内的编辑版本，适合当"纯原件保底"方案。

## 第 4 步：导出虚拟机里的第二账号

两条路线任选：

- **A（推荐，最省事）**：第二账号如果照片都在 iCloud 里，**根本不用进虚拟机**——直接在 Mac 上用 icloudpd 登录第二个 Apple ID，拉到 `/Volumes/Archive22T/Photos/account2-vm/`。
- **B（虚拟机里有仅本地、未上云的照片时）**：在虚拟机里同样装 osxphotos，把 22T 盘（或一个共享文件夹）挂进虚拟机，跑与第 3 步相同的导出命令，目标目录改成 `account2-vm`。

## 第 5 步：对账验证（删除前的硬性关卡）

```bash
# 1. 导出报告里有没有失败项
grep -i "error\|missing" /Volumes/Archive22T/Photos/dean-main-report.csv

# 2. 硬盘上的媒体文件数 vs Photos App 里显示的照片+视频总数
find /Volumes/Archive22T/Photos/dean-main -type f ! -name "*.xmp" ! -name "*.csv" | wc -l
# （因含 _edited 和 Live Photo .mov，数字应 ≥ Photos 显示的总数）

# 3. 生成校验和清单，留作日后搬到服务器时验证
find /Volumes/Archive22T/Photos -type f -exec shasum -a 256 {} \; > /Volumes/Archive22T/Photos/checksums.sha256
```

再抽查十几张不同年份的照片能否正常打开、Live Photo 视频是否存在。**全部通过才进入第 6 步。**

## 第 6 步：安全释放 MacBook 空间（不误删云端）

正确顺序，一步都不要颠倒：

1. **系统设置 → [你的名字] → iCloud → 照片 → 关闭**，选「**从 Mac 移除**」。⚠️ 这只删除本机缓存，**iCloud 云端的照片原封不动**。
2. 退出 Photos App，把 `~/Pictures/Photos Library.photoslibrary` 拖入废纸篓并清空 → 本机空间全部释放。
3. **iCloud 云端这份先留着**，等你办公室服务器（RAID1 + 备份）上线、硬盘内容复制过去形成第二份之后，再去 icloud.com 删除照片并清空「最近删除」、降级订阅。
4. 虚拟机账号同理。

这样任何时刻你都至少有两份完整数据（22T 盘 + iCloud），永远不裸奔。

## 第 7 步：用 Immich 管理（开源自托管）

**推荐 [Immich](https://immich.app)**：2025 年底已发布稳定版，是目前最活跃的开源自托管照片方案——手机 App 自动备份、人脸/物体识别、时间线体验接近 Google Photos。正好部署在你计划中的办公室服务器上（Docker Compose 一键起，你的 UGREEN/自建 GPU 服务器方案都能跑）。

针对你这个归档的最佳接法是 **External Library（外部库）**：

- 把 22T 盘的 `Photos/` 目录以**只读**方式挂给 Immich 容器，Immich 只做索引、缩略图和 AI 识别，**不移动不改写你的文件**——`年/月` 文件夹结构永远是干净的、不被任何软件绑架的原始档案。
- 两个账号 → 在 Immich 里建两个用户，各自挂 `dean-main/` 和 `account2-vm/` 作为外部库；手机今后新照片直接用 Immich App 自动备份到服务器。
- XMP sidecar 里的关键词、评分、GPS 会被 Immich 读取。

备选：**PhotoPrism**（单容器更轻，无多用户免费版），**digiKam**（纯桌面软件，不需要服务器，直接打开硬盘目录管理），**Ente**（端到端加密，偏云服务模式）。你的场景（多账号 + 未来服务器 + 手机访问）Immich 是最优解。

## 时间预期与顺序总结

```
[0] 格式化硬盘、建目录            （半小时）
[1] 补齐/确认 iCloud 原件         （视库大小，数小时~数天挂机）
[2-4] osxphotos 导出两个账号      （可中断续传，数小时~数天）
[5] 对账验证 + 校验和             （1小时）
[6] 关 iCloud 同步 → 删本机库     （半小时，云端保留）
[7] 服务器上线后：拷贝到 RAID → Immich 外部库 → 最后才清 iCloud
```
