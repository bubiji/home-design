| 检查项 | 结论 | 证据 |
|---|---|---|
| 假容量 | ✅ 排除 | 精确容量值吻合;盘尾最后 100MiB(204800 扇区)实读零错误;盘上已有 5.7TB 真实数据 |
| 坏道 | ✅ 零迹象 | SMART 5/196/197/198 全 0;盘头至盘尾 25 处物理抽读零错误;40/40 文件 SHA-256 校验通过 |

## 实测性能基线(USB, 供日后对比)

- 顺序读:盘头 247 MB/s → 25% 248 → 50% 233 → 75% 192 → 盘尾 125 MB/s(正常 ZBR 递减曲线)
- 随机位置 8MiB 读:90–222 MB/s

## 关键踩坑记录

1. macOS 无法读 USB 盘 SMART(内核无 SCSI/SAT 直通),与硬盘盒无关;解法 = Linux 虚拟机 USB 直通。
2. `osascript ... with administrator privileges` 弹窗授权不继承终端的「完全磁盘访问权限」,root 读 /dev/rdisk 仍报 Operation not permitted;解法 = 在已授权 FDA 的普通终端窗口手动 sudo。
3. 会话内/无 TTY 环境 sudo 无法输密码;解法 = 新开终端窗口。
4. 原始设备 `dd bs=512` 每块一次 USB 事务(~1.6ms),100MiB 耗时 338 秒;应改用 `bs=1m`。
5. UTM 的 macOS 客户机(Apple 虚拟化框架)不支持 USB 直通;必须用 Linux 客户机。
6. 磁盘工具「急救」只查文件系统结构,不查坏道。

## 维护计划

- 每 1–2 个月:Ubuntu 直通复查 `smartctl -a`,盯 ID 5/197/198(保持 0 → 继续用;增长 → 立即迁数据换盘)
- 定期抽样重跑 `checksums.sha256` 校验(盘上约 9 万条记录)
- 保持 NAS 双副本;备份盘不兼任活跃工作盘
- 大量拷贝时保证通风,避免再触 60℃
